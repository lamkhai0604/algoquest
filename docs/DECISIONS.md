## Technical

| ID | Decision | Rationale and alternatives | Status | Authority / date | Scope |
| --- | --- | --- | --- | --- | --- |
| D-030 | **Stack option B, API-first**: React 19 + Vite + TypeScript single-page app (`frontend/`) and a Spring Boot 4.1 / Java 21 modular monolith (`backend/`) exposing `/api/v1`, PostgreSQL with Flyway. | The product may grow (organizations, other clients); a separate API serves every client and keeps authorization in one backend. Rejected: option A (Next.js + Supabase) — faster to start, harder to extend. | Approved | PO, 2026-11-06 | Architecture |
| D-031 | **AI grading: Google Gemini API free tier, a Flash-family model** (`gemini-3.5-flash-lite` by default; `gemini-3.8-flash` allows only about 20 free requests/day, too few for daily use), called only from the backend behind a `Grader` interface; a `FakeGrader` for tests and smoke runs. Confirmed by the grading test on 2026-11-07 (T-005): NFR-03 met with prompt v2, which traces the learner's steps on an example before scoring. Paid models only with approval (D-006). | Only option with a no-cost tier among those evaluated. Free-tier prompts may be used by the provider to improve its products; acceptable because answers contain no personal data (NFR-07). | Approved | PO, 2026-11-06 | FR-05 |
| D-032 | **Java code runs on Judge0 CE through RapidAPI's free Basic plan (50 submissions/day)** behind a `CodeRunner` interface, with a daily quota guard. | Browsers cannot run Java; Judge0 is open source with a no-cost plan sufficient for one user. Self-hosting Judge0 is the fallback. | Approved | PO, 2026-11-06 | FR-07 |
| D-033 | **Content as files** in `content/` (levels, lessons as Markdown + JSON for walkthroughs and quick checks, problems as JSON), validated at backend startup and in CI, packaged into the backend image. Only progress lives in the database. | Reviewable in pull requests, versioned with the code, no authoring UI needed; only the backend reads answer keys and tests. | Approved | PO, 2026-11-06 | FR-03, FR-04 |
| D-034 | **Access design**: module `access` owns users, role assignments with an optional scope, a permission catalogue, and a Spring `PermissionEvaluator`; endpoints use `@PreAuthorize("hasPermission(...)")`; the game domain never checks permissions. The first Owner is seeded from `OWNER_EMAIL`; the last Owner cannot be removed; admin actions are audit-logged in the same transaction. | Authorization stays in one place, so organizations (FR-19) add roles and scopes instead of rewriting endpoints. Alternative: an `isAdmin` flag — simpler now, but every check would need rewriting for organization roles. | Approved | PO, 2026-11-06 | FR-17, FR-18, NFR-10 |
| D-035 | **JavaScript code is checked without sending expected outputs to the browser**: the browser receives only test inputs, runs the code in a Web Worker (5 s limit), and posts the outputs; the backend compares them with the expected outputs. | Free and unlimited; expected outputs stay private. Tradeoff: a learner can fake outputs, which only affects their own score while there is a single user; before graded classes, move JavaScript to Judge0 or a server sandbox (T-505). | Approved | PO, 2026-11-06 | FR-07 |
| D-036 | **Sign-in**: Spring Security OAuth2 login with Google and GitHub on the backend; on success the backend redirects with a one-time code (60 s, single use, stored hashed) that the SPA exchanges for the app's own HMAC-signed JWT (4 h, user ID only, no refresh token). The SPA keeps it in memory and `sessionStorage` and sends it as a Bearer header. | No passwords stored; the JWT never appears in a URL. Tradeoff: `sessionStorage` is exposed to XSS, mitigated by React escaping and no raw HTML rendering. Re-login after 4 h is one click. | Approved | PO, 2026-11-06 | FR-01, NFR-02 |
| D-037 | **Hosting** (when deployment is approved): frontend on Vercel Hobby, backend on Render free web service (Docker; sleeps after 15 minutes idle), database on Neon Free. The frontend shows a "waking the server" state. | All $0. Vercel Hobby covers personal projects, which matches the project's purpose (D-022); any change of hosting is a new decision (D-006). | Approved | PO, 2026-11-06 | NFR-01 |
| D-038 | **Automated records check in CI** (`docs.yml`, runs on every push and PR that changes Markdown): fails on broken relative links, undefined or duplicated requirement/task/decision IDs, non-English text in records (test data excluded), conversational markers such as "in chat", links to private workspaces (for example `claude.ai`), and references to the internal engineering guidelines (D-003). | Enforces the record style (WORKFLOW.md, Records) the same way for every contributor, human or AI; reading the rules alone does not guarantee compliance. | Approved | PO, 2026-11-06 | Records, NFR-08 |
| D-040 | **XP rebalance for the first release.** The level bar is the sum of one full pass through the level: base 15 XP, Medium +9, time bonus +5, so Easy is 20 and Medium is 29 (3 Easy + 3 Medium = 147), plus 5 XP for the lesson's quick check. Level XP target is **150** for Levels 1–3, which share the same content shape; a level's target is set again when its content changes. Hard bonus is +20. Hints, the time limit, the code bonus (×2), and the practice round (70% of the target opens it; Done +10) are unchanged. Updates D-015; the numbers stay open to tuning after the trial. | Before this change a full pass gave 180 XP against a 100 XP bar, so the bar filled after about four problems and "full bar" did not mean "level finished". | Approved | PO, 2026-11-11 | FR-08, FR-09 |
| D-041 | **The quick check awards 5 XP once per level**, when every question has been answered correctly. The result is stored per player and level, so leaving the lesson and coming back shows the finished state. The 5 XP counts toward the level bar. | The lesson should be read and understood before the problems; a stored result also removes the repeated-answer loophole. | Approved | PO, 2026-11-11 | FR-03 |
| D-042 | **Problems open in order.** In a level the first problem is open; the next one opens when the previous one has been solved (score 70 or more). A problem that has been graded opens on its last result, with Back, Retry (after a confirmation), and Next. Score 100 shows a short celebration. | Guides the learner through the level and avoids submitting unread problems; the result page is the learner's record of the attempt. | Approved | PO, 2026-11-11 | FR-04 |
| D-043 | **The time bonus counts active working time.** The solve page sends a heartbeat every 30 seconds while the page is visible; the server adds up active seconds per player and problem. Leaving the page pauses the clock; coming back asks whether to continue or start again (starting again clears the draft and the clock). Past the limit the clock stays visible but muted with a note that the time bonus is gone; the problem can still be solved. A problem with active time and no graded attempt shows a Paused tag in the list. Replaces the first-opening clock of Sprint 3. | A closed laptop or a long break should not cost the bonus; the server still owns the clock. | Approved | PO, 2026-11-11 | FR-04, FR-08 |
| D-044 | **A reusable scoring guide** under the solve page and the test page explains the four criteria, the pass mark (70), the XP per difficulty, the time limits and what happens after them, and the hint penalty. Levels that cannot be opened yet are not listed on the profile. | The learner can see how an answer is judged before submitting it. | Approved | PO, 2026-11-11 | FR-04, FR-05, FR-12 |
| D-045 | **Sign-in background: a live graph search.** The sign-in page draws a breadth-first search spreading across a drifting graph, one layer at a time, in the theme's colours, behind the sign-in card. Canvas only, no library or image file; paused while the tab is hidden; still when the system asks for reduced motion. | Gives the first page an algorithm theme without the weight or blur of a generated image; chosen from five prototypes (typed code, character rain, editor windows, graph search, sorting bars). | Approved | PO, 2026-11-12 | FR-01 |
| D-046 | **The code editor is built in-house for this release**: a textarea with line numbers, Tab indentation, monospace text, and basic keyword highlighting, without a third-party editor library. | No new dependency or lockfile change; enough for short solutions. A library editor (CodeMirror) can replace it later behind the same component. | Approved | PO, 2026-11-12 | FR-07 |
| D-047 | **Game rules are stored as one configuration record in the database** and read at runtime: XP values, time limits, hint quota and window, pass mark, practice XP, quick-check XP, and level target. The values of D-040 are the defaults. | Tuning after each trial (T-407) without a deployment; one place for every number the rules use. | Approved | PO, 2026-11-12 | FR-18.3, OQ-03 |
