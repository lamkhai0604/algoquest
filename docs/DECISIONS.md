## Product

| ID | Decision | Status | Authority / date | Scope |
| --- | --- | --- | --- | --- |
| D-010 | Name **AlgoQuest**, slogan **"Don't let Algorithm beat you"**. App UI and lessons in **English**. | Approved | PO, 2026-11-06 | Product |
| D-011 | The first release has a **single real user** (the PO) for acceptance testing. Social features (leaderboard, other players) use **dummy data**. Expansion is considered only after a trial period. | Approved | PO, 2026-11-06 | Product, FR-14 |
| D-012 | Levels are topics ordered **easy → hard**; the number of levels is not fixed (17 proposed in SRS §6). The first test build covers **levels 1–3**. | Approved | PO, 2026-11-06 | FR-02, roadmap |
| D-013 | Answers are **typed explanations** graded by AI with a 4-criterion rubric (pattern 40, steps 30, complexity 20, edge cases 10). Voice answers later. | Approved | PO, 2026-11-05 | FR-05 |
| D-014 | **Optional code** after a passing explanation, in **JavaScript or Java**; all hidden tests passing doubles the problem's XP. | Approved | PO, 2026-11-06 | FR-07 |
| D-015 | **Scoring**: base 20 XP; extra credit +10 Medium, +25 Hard, +5 within time (Easy 15 / Medium 25 / Hard 40 min); code passing ×2; each hint −20%. Level XP target = 100 + 25 × (level − 1). Starting values, tuned after the levels 1–3 trial. | Approved | PO, 2026-11-06 | FR-08 |
| D-016 | **Progression**: 70% of the level bar opens the practice round (redo solved problems, Done = +10 XP); a full bar opens the level-up test (3 new problems, about 2 hours). Test score < 70 → retake; 70–99 → next level opens **Easy problems only**; 100 → whole next level. Retakes are always allowed; unlocked content stays reviewable. | Approved | PO, 2026-11-06 | FR-09, FR-10 |
| D-017 | **Hard test mode** (optional): 5 problems, 1 h 45 min; +30 XP per passed problem to the next level's bar. | Approved | PO, 2026-11-06 | FR-11 |
| D-018 | **Hints**: 3 tiers per problem; at most **3 hints, refilled every 5 hours**. A monthly **VIP** plan for more hints is future work; this release shows a placeholder with dummy data and no payment. | Approved | PO, 2026-11-06 | FR-06, FR-15 |
| D-019 | **Battle mode** is out of this release; at most a dummy placeholder. | Approved | PO, 2026-11-06 | FR-16 |
| D-020 | **Content is original** in a LeetCode-like format (statement, examples, constraints, hidden tests) with a "similar LeetCode problem" reference; no third-party problem text is copied. Lessons follow the 9-part template in CONTENT-GUIDE.md. | Approved | PO, 2026-11-06 | Content |
| D-021 | **Sign-in with roles in this release**: Owner (full control) and Player (default). Authorization uses named permissions with an optional scope per role assignment, plus an audit log, so future roles can be added without changing the game rules. | Approved | PO, 2026-11-06 | FR-17, FR-18 |

## Technical

| ID | Decision | Rationale and alternatives | Status | Authority / date | Scope |
| --- | --- | --- | --- | --- | --- |
| D-030 | **Stack option B, API-first**: React 19 + Vite + TypeScript single-page app (`frontend/`) and a Spring Boot 4.1 / Java 21 modular monolith (`backend/`) exposing `/api/v1`, PostgreSQL with Flyway. | The product may grow (organizations, other clients); a separate API serves every client and keeps authorization in one backend. Rejected: option A (Next.js + Supabase) — faster to start, harder to extend. | Approved | PO, 2026-11-06 | Architecture |
| D-031 | **AI grading: Google Gemini API free tier, a Flash-family model** (`gemini-3.5-flash-lite` by default; `gemini-3.8-flash` allows only about 20 free requests/day, too few for daily use), called only from the backend behind a `Grader` interface; a `FakeGrader` for tests and smoke runs. Final model choice is confirmed when the grading test (T-005) meets NFR-03. Paid models only with approval (D-006). | Only option with a no-cost tier among those evaluated. Free-tier prompts may be used by the provider to improve its products; acceptable because answers contain no personal data (NFR-07). | Approved | PO, 2026-11-06 | FR-05 |
| D-032 | **Java code runs on Judge0 CE through RapidAPI's free Basic plan (50 submissions/day)** behind a `CodeRunner` interface, with a daily quota guard. | Browsers cannot run Java; Judge0 is open source with a no-cost plan sufficient for one user. Self-hosting Judge0 is the fallback. | Approved | PO, 2026-11-06 | FR-07 |
| D-033 | **Content as files** in `content/` (levels, lessons as Markdown + JSON for walkthroughs and quick checks, problems as JSON), validated at backend startup and in CI, packaged into the backend image. Only progress lives in the database. | Reviewable in pull requests, versioned with the code, no authoring UI needed; only the backend reads answer keys and tests. | Approved | PO, 2026-11-06 | FR-03, FR-04 |
| D-034 | **Access design**: module `access` owns users, role assignments with an optional scope, a permission catalogue, and a Spring `PermissionEvaluator`; endpoints use `@PreAuthorize("hasPermission(...)")`; the game domain never checks permissions. The first Owner is seeded from `OWNER_EMAIL`; the last Owner cannot be removed; admin actions are audit-logged in the same transaction. | Authorization stays in one place, so organizations (FR-19) add roles and scopes instead of rewriting endpoints. Alternative: an `isAdmin` flag — simpler now, but every check would need rewriting for organization roles. | Approved | PO, 2026-11-06 | FR-17, FR-18, NFR-10 |
| D-035 | **JavaScript code is checked without sending expected outputs to the browser**: the browser receives only test inputs, runs the code in a Web Worker (5 s limit), and posts the outputs; the backend compares them with the expected outputs. | Free and unlimited; expected outputs stay private. Tradeoff: a learner can fake outputs, which only affects their own score while there is a single user; before graded classes, move JavaScript to Judge0 or a server sandbox (T-505). | Approved | PO, 2026-11-06 | FR-07 |
| D-036 | **Sign-in**: Spring Security OAuth2 login with Google and GitHub on the backend; on success the backend redirects with a one-time code (60 s, single use, stored hashed) that the SPA exchanges for the app's own HMAC-signed JWT (4 h, user ID only, no refresh token). The SPA keeps it in memory and `sessionStorage` and sends it as a Bearer header. | No passwords stored; the JWT never appears in a URL. Tradeoff: `sessionStorage` is exposed to XSS, mitigated by React escaping and no raw HTML rendering. Re-login after 4 h is one click. | Approved | PO, 2026-11-06 | FR-01, NFR-02 |
| D-037 | **Hosting** (when deployment is approved): frontend on Vercel Hobby, backend on Render free web service (Docker; sleeps after 15 minutes idle), database on Neon Free. The frontend shows a "waking the server" state. | All $0. Vercel Hobby is non-commercial: any paid offering (FR-19) needs paid hosting, decided at that time (D-006). | Approved | PO, 2026-11-06 | NFR-01 |
| D-038 | **Automated records check in CI** (`docs.yml`, runs on every push and PR that changes Markdown): fails on broken relative links, undefined or duplicated requirement/task/decision IDs, non-English text in records (test data excluded), conversational markers such as "in chat", and links to private workspaces (for example `claude.ai`). | Enforces the record style (internal guidelines §3) the same way for every contributor, human or AI; reading the rules alone does not guarantee compliance. | Approved | PO, 2026-11-06 | Records, NFR-08 |
